# Requirements Discovery Working Notes

## Purpose

Working notes from ongoing requirements discovery with KMD and other stakeholders, feeding updates back into the core requirements documents ([`docs/02_Business_Requirements.md`](../02_Business_Requirements.md), [`docs/03_Software_Requirements_Specification.md`](../03_Software_Requirements_Specification.md), [`docs/04_Functional_Requirements.md`](../04_Functional_Requirements.md)) rather than living as permanent scattered notes.

> Version: 1.0 | Author: ClimateShield Nexus Product Team | Last Updated: 2026-07-27

## Process

1. Discovery session notes captured here as `discovery-YYYY-MM-DD-<topic>.md` (use [`docs/templates/meeting_notes_template.md`](../templates/meeting_notes_template.md)).
2. Any resulting requirement change is incorporated into the relevant core document with a Revision History entry.
3. Once incorporated, the discovery note is retained here for historical traceability but is no longer authoritative — the core document is.
